# 査読者の懸念に応える実験設計（2026-10-26）

準拠本文：トイ作成時点の本文（公開する原稿との関係は総括 0 節）。三原理は SM・EU・FR。原理関連構造的機能は 7 群（def:principle_related_functions）。

## 0. 出発点：「三原理に従った系」をどう定義するか

最初に、査読者が最も突きやすい点を押さえておく。

- 本文は三原理を「外部から課される価値規範または目的関数ではない」と定め、時刻別の充足述語として与えている。
  - SM は $x_t\in K$。
  - EU は臨界必要要因が実現した $e_t$ で充足されていること。
  - FR は $\mathcal{D}_{\mathrm{FR}}$ 上で $A_t\neq\emptyset$ であること。
- EU は環境が決め、FR は $(x_t,e_t)$ が決める。どちらも個体が直接「従う」ことのできる行動規則ではない。
- したがって「従った系と従わなかった系」を素朴に作ると、二つの欠陥が生じる。
  1. **範疇の誤り**：原理を目的関数として最適化する制御器を作ることになり、本文の位置づけと矛盾する。
  2. **循環**：原理に合わせて設計した系を、原理の充足率で評価することになる。結果は設計から自明になる。

そこで比較の対象を次の二水準に置き換える。どちらも本文の既存概念で表現できる。

| 水準 | 「従う」の意味 | 本文の根拠 |
|---|---|---|
| 軌道水準 | 核維持応答 $u_s\in U^{\mathrm{Viab}}(x_s)$ を選び続ける | def:kernel_response、def:kernel_response_acquisition、prop:kernel_maintenance |
| 機構水準 | 原理関連構造的機能（分類A の 7 群）を備えている | def:principle_related_functions |

評価指標は、原理の述語そのものではない量に置く。主なものは崩壊到達時刻 $T_{\mathrm{col}}$、地平内の生存、機能的終端の有無、閉塞からの回復回数である。SM の充足時間割合などの原理由来の量も記録するが、比較の主指標には使わず、循環のおそれを明記して参考値として載せる。

## 2. 実験群

各実験に、問い、設計、指標、事前に固定するもの、結果の読み方、論文への寄与の上限を書く。

### E1 軌道水準の比較：核維持応答の選択とその他の方策

- **問い：** prop:kernel_maintenance は「$e_s\in E_{\mathrm{req}}(x_s)$ が続く限り」核にとどまることを保証する。その前提が破れる現実の軌道で、何が起きるか。証明が扱わない領域を観察する。
- **方策（いずれも同じ世界、同じ背景列）：**
  - P-Viab（オラクル）：真の $\mathrm{Viab}_f(K)$ を用い、$U^{\mathrm{Viab}}(x_t)$ から選ぶ。空なら $A_t$ から、それも空なら $u_\emptyset$ を選ぶ。
  - P-A（一段オラクル）：真の $A_t$ から選ぶ。一段階だけの可行性保持である。
  - P-mech：v2 の TIPA 機構。真値を使わない。
  - P-greedy：energy だけを見る反射則。
  - P-fixed：決定論的な擬似乱数列による固定行動列（確率は導入しない）。
  - P-wait：常に $u_\emptyset$。
- **指標：** $T_{\mathrm{col}}$。$e_t\notin E_{\mathrm{req}}(x_t)$ の時刻数。$x_t$ が核から出た時刻と、そのときの $e_t$ が $E_{\mathrm{req}}$ の外だったか。
- **読み方：**
  - P-Viab が核から出た時刻のすべてで $e_t\notin E_{\mathrm{req}}$ になっていれば、命題との整合を確かめる回帰検査になる。そうでない時刻があれば、実装の誤りである。
  - P-Viab と P-A の差は、多段の頑健性と一段の可行性の違いを示す。
- **寄与の上限：** 命題を補強するものではない。命題の前提が破れる状況の記述例を与える。オラクル方策は個体が実現できる方策ではないことを明記する。

### E2 機構水準の除去実験：原理関連構造的機能 7 群

P-mech から一つずつ機能群を除き、その他は同一に保つ。除去の仕方は「機能を定数や無情報な出力に置き換える」に統一する。構造の形（型）は保つ。

| 除去する機能群（def:principle_related_functions） | トイでの実装上の除去 |
|---|---|
| 情報取得・統合 | M1 の統合を外す（直前の観測だけ、記憶なし） |
| 可行性感応評価 | M2 の $\Pi_{\mathrm{eval}}$ を定数にする（Priority と欠乏信号が出ない） |
| 応答可能性評価・再構成 | 先読みを外し、候補生成を固定集合にする |
| 環境利用・外部結合評価 | 必要環境要因（heat・food）に関わる要請と目的を外す |
| 応答形成・選択 | 適合度を一定にし、選択射影の既定順だけで選ぶ |
| 時間横断的情報保持・更新 | Update を恒等写像にする（学習と忘却なし） |
| 物理的感知・作用・基盤維持 | PSL-4 と repair を外す |

追加の除去として、自動化（ルーティン）、関係（signal・give）、救助の担い手（相手・ドローン・組織）を外す条件も置く。

- **指標：** E1 と同じ。加えて、閉塞の種類 (B1)/(B2) の内訳と、閉塞の終わり方（自律か $e_t$ 経由か）。
- **読み方：** 各除去で $T_{\mathrm{col}}$ の分布（構成の件数）がどう動くかを報告する。悪化しない除去も、そのまま報告する。
- **寄与の上限：** 「このトイの実装では、機能群 X の除去で崩壊が早まる構成が N 件中 k 件あった」まで。機能群が一般に必要であることの証明にはならない。本文の「構成的必要性」は §1.2.1 の環境に相対する概念的な主張であり、トイはその例示にとどまる。

### E3 原理の述語と結果の関係（循環を避けた分析）

- **問い：** EU・FR・$\mathrm{Hor}_f$・$\mathrm{Viab}$ の判定は、原理を使わない素朴な指標（energy の水準など）よりも、崩壊の接近を早く、または別の形で示すか。
- **設計：** E1・E2・E4 のすべての記録について、崩壊した軌道の各時刻に崩壊までの残り時間を付ける。そのうえで、各指標が初めて警告状態になった時刻と崩壊時刻の差（先行時間）を件数で集計する。比べる指標は次のとおり。
  - $\mathrm{Hor}_f$ が有限
  - 核から出る
  - (B2) の閉塞
  - 状態帯 Z1
  - energy≤5
- **読み方：** 原理由来の指標が素朴な指標より先行時間で劣るなら、それもそのまま報告する（Q1 への正直な回答になる）。
- **寄与の上限：** 一つのトイ世界での比較である。診断量としての一般的な有用性は主張しない。確率・統計の語は使わず、件数と割合で書く。

### E4 頑健性と事後調整への対処（全実験に共通の手続き）

1. **事前登録：** 実験前に、仮説、判定規則、数値、指標、読み方を文書で固定し、そのハッシュ（md5）を記録する。実験後の変更は、版を分けて報告する。
2. **背景列の分割：** 機構の調整には背景列（seed）1〜10 だけを使い、評価には 11〜60 の 50 本を使う。
3. **数値の掃引：** 主要な世界の数値（eat_gain、regen_period、厳寒の長さ、贈与量、代謝）を各 3 水準にとり、格子として掃引する。結論がどの範囲で保たれるかを件数で示す。
4. **判定規則の変種：** 状態帯、Recover の地平、(FT-2) の規則に、それぞれ 2〜3 の変種を用意する。結論が規則に依存するかを示す。
5. **作り手と別の検証者：** 対応表、事前登録文書、コードを、作成に関わっていない検証者が照合する。

### E5 既存理論との弁別（Q4）

- **問い：** 標準的な生存可能性理論（$K$ と生存可能性核だけ）による分類と、ACS の分類が食い違う状態や時刻はあるか。
- **設計：** 同じ記録に、二つの分類を並べる。
  - 基準側：$K$、標準の生存可能性核（全 $e\in E_{\mathrm{ext}}$ に対する頑健版、または $\exists e$ 版）。
  - ACS 側：$E_{\mathrm{req}}$ 相対の核、(B1)/(B2)、FT と CS の区別、Recover。
  - 食い違いの件数と典型例を示す。例：標準の頑健核では空になるが、$E_{\mathrm{req}}$ 相対の核では空でない状態。$K$ の外で FT にも CS にもならず回復する時刻。
- **寄与の上限：** ACS の概念が標準理論と区別できる内容をもつことの例示まで。優越性は主張しない。本文の「標準 Viability Kernel との同一性は非主張」との関係を具体化する。

### E6 MinACS：手で検証できる最小例と非冗長性（Q1・Q5）

- **仕様（案）：**（設計時の案。実装した MinACS は 2 セル（避難所・資源）、energy{0..5}、合計 72 状態である。現行の仕様は `minacs/model.py` の冒頭と E6 報告を参照）
  - 1 次元の 4 セル（避難所・資源・通路 2）。
  - $X$ = 位置 × energy{0..4} × temp{0..2} × 構造{0,1}。合計 120 状態。
  - $U$ = {待機, 左, 右, 食べる}。
  - $E_{\mathrm{ext}}$ の局所像 = 寒さ{0,1} × 資源{0,1}。
  - $E$ = {熱, 食料}。
  - 内部モデルは 1 ビットの記憶（資源の有無の信念）と 2 段の評価だけ。
- **全状態での厳密計算：**
  - $K$、$A$、$\mathrm{Crit}^{(1)}_\eta$、$\mathcal{D}_{\mathrm{FR}}$、$\mathrm{Viab}_f(K)$、$\mathrm{Hor}_f$、$U^{\mathrm{Viab}}$ を計算する。
  - $\mathrm{Viab}^{\mathrm{resp}}_f(K)$ を、記憶 1 ビットを含む積空間で計算する。
  - CR-1a(ii)、(SC-2)、(FT-2) を全数検査で確かめる。格子検査ではなく、有限全数による証明にする。
  - すべてを表として付録に載せられる規模にする。
- **非冗長性の分離例：**
  - SM・EU・FR の各対について、一方が真で他方が偽となる状態と環境の組を全数から抽出する。
  - 7 タプルの各成分を退化させたとき（$M$ を単点、Update を恒等、$E$ を空など）に、どの定義が空虚になるか、または定義できなくなるかを表にする。
- **最小性の主張の上限：** 「この例より小さい例が存在しない」ことは主張しない。主張するのは「各概念が区別をもつ最小規模の一例」まで。
  - 状態数の下界を示すなら、各区別に必要な状態数を数える命題を別に立てる必要がある。これは本文の主張範囲外とする。

### E7 推定誤差のもとでの乖離（Q6）

- **問い：** 個体の内部評価（$\Pi_{\mathrm{eval}}$、機構の可行性判断）と真値の乖離は、閉塞や崩壊とどう関係するか。
- **設計：** 感知の健全度、記憶の忘却速度、内部モデルの誤り（例：寒さの見積もりのずれ）を段階的に変える。次を記録する。
  - $\Pi_{\mathrm{eval}}$ と $\Pi$ の符号不一致の時刻数
  - $u_t\notin A_t$（選択の責務違反）の時刻数
  - $T_{\mathrm{col}}$
- **寄与の上限：** §9 の未解決問題（推定誤差）への具体例。誤差の閾値などの一般則は主張しない。

### E8 第二の領域（Q7）

- 格子の採食とは構造の異なる領域を一つ作り、E1・E2 の主要部分を繰り返す。候補は二つ。
  - 熱と燃料を管理する定常系（移動がない）。
  - 二つの資源の交換に依存する系（関係が必須になる）。
- 判定層（judge）は共通に使えるように、領域に依存する部分（$f$、$\eta$、$\lambda$ の像）を差し替え可能にする。
- **寄与の上限：** 判定層が領域をまたいで適用できることの例示。領域一般への妥当性は主張しない。

## 3. 結果の報告形式

- 各実験について、事前登録した仮説ごとに「支持／不支持／判定不能」を件数つきで示す。
- 不支持の結果も本文と同じ重みで載せる。
- 図は 3 種類に絞る。

  - E3 の先行時間の比較。
  - E6 の全状態表（付録）。
- 論文本文には持ち込まず、GitHub の付属物とする。本文で触れる場合も、存在の水準の一文にとどめる（著者判断）。

## 5. 予想される弱点（設計段階での自己批判）

- E2 の「除去」の実装は一意でない。除去の仕方によって結果が変わりうるため、除去の実装も事前登録の対象にする。
- E1 のオラクル方策は計算量が大きい。v2 の世界では $\mathrm{Viab}_f(K)$ を証明書方式でしか判定できないので、「未決定」の時刻での方策を規則として事前に固定する必要がある。
- E3 は崩壊した軌道だけを使うと選択の偏りが入る。崩壊しなかった軌道での誤警報の件数も併記する。
- 50 本の背景列と数値の格子を組み合わせると、実行回数が数千になる。検査（checks）は代表構成に限り、判定層は全構成で回す。
- いずれの実験も、本文の命題の真偽を左右しない。トイが示せるのは、例示、反例、適用上の帰結に限られる。この点を報告の冒頭に明記する。
