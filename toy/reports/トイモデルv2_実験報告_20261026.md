設計と対応表は `README.md` にある。本報告は 8 シナリオを各 300 ステップ実行した実測値をまとめる（`long` だけは 600 ステップ）。

## 1. 検査

全 8 シナリオで `checks.txt` の NG は 0 件（実測）。

- 初回の実行で `alone` に NG が 2 件出た。原因は検査側の証拠の作り方にあった。
  - $\eta_{\mathrm{food}}$ の CR-1a(i)/CR-1c の証拠は、贈与がないと食料に届かないセルに置いていた。
  - CR-2b(iv) の証拠は状態の対を一つしか試していなかった。
  - 証拠を資源セルの枯渇の列と、16 状態からの探索に改め、`default`・`harsh`・`alone` を再実行した。

## 3. default の経過の読み

`events.md` と `trace_*.csv` からの読みである。

1. **0〜150：維持。** 状態帯は主に Z0。1 回目の厳寒（60〜67）は両個体とも避難所で越え、閉塞は生じなかった。資源の近くでは自動化（比較を経ないルーティン応答、モード 3C）が多く現れた（i：136 時刻、j：90 時刻）。
2. **153：閉塞と回復。** 2 回目の厳寒の始まりに、両個体で (B1) の閉塞が生じた（臨界必要要因 heat の非充足）。i は 154 に、j は 156 に、自律的に（自分の行動と環境で）$A_t\neq\emptyset$ に戻った。
3. **160〜178：救助と崩壊。** j は (B2) の閉塞（$\mathcal{D}_{\mathrm{FR}}$ 上で FR が偽）を繰り返した。組織（161）、ドローン（163〜165）、相手 i（170、178）の贈与が $e_t$ を通じて届いた。
   - 161・163・170 の閉塞は贈与で解消した。
   - 178 の贈与の時点では $A_t$ は空のままだった。
   - j は 178 に機能的終端、180 に崩壊に至った。
4. **243〜260：最後の閉塞と崩壊。** 3 回目の厳寒（240〜259）で、i は (B1) と (B2) の閉塞を経験した。ドローンの贈与で一度回復したが、260 に機能的終端と崩壊に同時に至った。
   - i の Recover は 165 で `110`、253 で `100`（inject だけが回復可能）だった。
   - 外的作用で回復しうる範囲が、崩壊の前に狭まっていく様子が記録に現れている。

## 4. 観察された形式の出現（実測、全シナリオ）

- 閉塞の二分 (B1)/(B2)：全シナリオで両方出現した。ただし rocky では (B1) は 0 件。
- 救助の担い手：
  - 相手の ACS（give）は default・harsh・cooperative・explorer・rocky で出現した。
  - 非 ACS のドローンは no_drone と alone 以外で出現した。
  - 組織の配分も出現した。
- PSL-4 の保護応答は rocky でだけ出現した（各個体 1 回）。その他のシナリオでは 0 回だった。
- 機能的終端が崩壊に先行した例（$T_{\mathrm{FT}}<T_{\mathrm{col}}$）：default の j、harsh の j、no_drone の両個体、explorer の j、rocky の両個体、long の両個体。
- alone は 300 ステップを崩壊なしで終えた。他個体との資源競合がないことが関係すると読めるが、比較実験はしていない（未検証）。

## 5. 限界

- 崩壊時刻はトイ規約の数値に強く依存する。調整の過程で、小さな変更で大きく動いた。シナリオ間の比較から一般的な傾向を述べることはしない。
- $\mathrm{Viab}_f(K)$ は証明書方式で判定しており、「未決定」が残りうる。
- $\mathrm{Viab}^{\mathrm{resp}}_f(K)$ と組織水準の EU・FR は計算していない。
- CR-1a(ii)・(SC-2)・(FT-2) の GRID 検査は格子上の検査とコードの目視によるもので、証明ではない。
